# AOF: инженерный аудит и исправления — 20 сентября 2026

## Вердикт

**NO-GO для mainnet.** Выполнены широкий проход и второй этап: on-chain reward receipts, ограниченная покупка marketplace, проверка локального намерения и дополнительные регрессии. Это **не полный независимый аудит всех путей исполнения**, не формальная верификация и не подтверждение deployed bytecode. Запрос «исправить всё и гарантировать production» этим проходом не закрыт.

Исходная точка: `c8c612ae4e2058a2a331dd15dc3735b3e696ec68`, рабочая ветка `arena/01a0c005-aof`. Текущий patch включает изменения on-chain логики, но они **не задеплоены**. Ключи/средства/production DB не использовались.

Предыдущие документы объявляли паки/кузницу и production-развёртывание готовыми. Такие утверждения больше не являются основанием для запуска. Защита возврата escrow не равна честной случайности, а успешная компиляция не равна безопасности экономики.

## Исправленные находки

### AOF-01 — High: обход центрального wallet proof через URL

`walletProof.ts` сравнивал `req.path` буквально; стандартный Express Router принимает `/Guild/Create/` как `/guild/create`. Неаутентифицированный запрос мог достичь обработчика записи, рассчитывающего на центральную проверку.

**Исправление:** сопоставление маршрутов учитывает регистр и trailing slash. Регрессия отправляет настоящие HTTP-запросы через Express и требует 401 для всех четырёх вариантов. Это не означает, что всякий новый маршрут автоматически защищён: явную карту необходимо поддерживать.

### AOF-02 — High: подпись не связывала HTTP method и path ID

Подписывались subject и body, но не адрес операции. Для динамических маршрутов вроде удаления alert в body отсутствует ID из URL; подписанное намерение могло быть изменено до первого использования.

**Исправление:** digest = SHA256(canonical JSON `{method, target, body_without_walletProof}`). Target включает path и query. Backend и frontend обновлены вместе. Старые body-only proofs намеренно больше не принимаются; это требует синхронного rollout. Добавлены negative tests на смену ID/method/query. Ограничена глубина JSON, ошибка возвращает 400 вместо rejected async handler.

### AOF-03 — High: allowlist стандартных программ пропускал опасные инструкции

SPL Approve/SetAuthority/CloseAccount и System Assign/nonce не становились безопасными от наличия program ID в allowlist. Старый guard проверял лишь часть переводов и мог игнорировать выдачу полномочий.

**Исправление:** opcode policy до симуляции; прямые Token/Token-2022 операции закрыты кроме строго ограниченного prep-mint, неразрешённые System/ComputeBudget — отказ. Контроль network fee, mint rent, decimals, canonical mint authority, отсутствия freeze authority, ATA derivation и числа ATA. ALT остаётся fail-closed. Guard перенесён на фактическую границу подписи с проверкой реального provider public key.

**Остаточный риск:** точная проверка намерения добавлена для marketplace buy (AOF-13), но НЕ для всех операций. Другие разрешённые AOF instructions могут выполнить дорогой CPI; max-price/slippage/deadline пока не покрывают каждую операцию. Нужны per-action instruction/account validation и simulation balance-delta limits. Не маркировать `safe: true` как гарантию отсутствия потерь.

### AOF-04 — High: signature/confirmation принимались за успешное исполнение

`authorityOnly` игнорировал `confirmation.value.err`. Frontend возвращал успех сразу после `signAndSendTransaction`. Legacy overload симуляции на frontend вызывался с несовместимыми options; backend legacy overload симулировал сообщение с обновлённым blockhash, а не обязательно проверяемые байты.

**Исправление:** симуляция legacy message через VersionedTransaction без замены blockhash; сохранение исходной подписи. Backend использует исходные blockhash/lastValidBlockHeight, finalized confirmation и проверку err. Transport timeout — отдельный `TransactionOutcomeUnknown`, а не «можно повторить». Frontend ждёт confirmed/finalized status и показывает pending/error вместо успеха. Обновлены также farm-trader и проверка результата admin relay.

### AOF-05 — High: повторная reward mint после неоднозначного RPC timeout

Inbox мог сбросить `claimed=false`, хотя отправленная транзакция уже попала в сеть. Новый запрос с новым idempotency key мог минтить повторно.

**Исправление, этап 1:** durable reservation; `claimSignature` записывается **до broadcast**; reserved/submitted/confirmed состояния. При неизвестном исходе резерв не освобождается. Archive pending claim запрещён.

**Этап 2:** `mint_resource_once` атомарно создаёт постоянный `RewardReceipt` PDA по `["reward_receipt", sha256("AOF_INBOX_REWARD_V1\0" + inboxID)]` и выполняет обе части mint. `init`, не `init_if_needed`; close-инструкции нет. Повтор одного ID не должен выпускать ресурс повторно даже с другим mint/получателем/amount/подписью или после восстановления старой DB. Размер — **121 byte с discriminator**; rent платит authority, он остаётся заблокированным. Общий mint helper сохраняет canonical mint/authority/perk проверки и использует u128 для промежуточной комиссии.

Backend читает finalized receipt, сверяет owner, ID, recipient, mint и gross amount. Совпадающая квитанция позволяет восстановить состояние DB. Конфликт помещает запись в `quarantined`, не в очередь повторной выплаты. Reconciler не переоткрывает уже выплаченную награду из-за ошибки duplicate retry. Cursor сохраняется в DB после каждой страницы: более 1000 unresolved записей не должны навсегда блокировать следующие. Один конфликт не прерывает весь batch; ошибки RPC/decode остаются fail-closed.

Миграции `202609200001`–`003` добавляют state/signature, version/mint snapshot, cursor и index. **Все существующие награды получают version=0 и требуют исторической сверки**, даже если раньше `claimed=false`; новые — version=1. Не присваивать старым наградам новые ID и не массово переводить version=0 в 1 ради обхода карантина.

**Граница гарантии:** один стабильный reward ID в новом mint-пути. Это не supply cap: legacy `mint_resource` и право authority создавать новые ID сохранены. Кража authority по-прежнему критична. ABI/layout, finalized reader, conflict/reconciliation/pagination и SQL migrations проверены локально; **исполнение/replay/atomic rollback Rust на validator ещё не проверено**. Добавлены соответствующие validator fixtures, но не выдаются за пройденные тесты.

### AOF-06 — High / economic: legacy randomness не гарантирует честный платный исход

`randomness.rs` использует secret + slot hash. Secret holder может выбирать раскрытие; expiry возвращает ставку/ресурсы. Forge on-chain принимает caller-selected commitment и требует authority для reveal; обычный HTTP-клиент не получает server secret. Поэтому это **не доказательство, что любой пользователь уже может бесплатно выигрывать через API**. Но протокол не обеспечивает trustless randomness/обязательный settlement и допускает привилегированное выборочное раскрытие, а odds паков читаются из изменяемого config на reveal, не из snapshot на commit.

**Митигировано, не реализовано заново:** новые pack/forge commits возвращают FeatureDisabled on-chain и 503 API; UI не создаёт даже подготовительный mint. Старые reveal/expire оставлены. Для повторного включения нужны authenticated request-bound VRF, snapshot экономических параметров, non-optional settlement и negative/runtime tests. Только backend-флагом защиту не обходить.

### AOF-07 — Medium / economic: округление долей LP

`amount / floor(assets / shares)` систематически выдаёт лишние доли по сравнению с `floor(amount * shares / assets)`. При широких u64 значениях withdrawal ошибочно переполнял промежуточное произведение.

**Исправление:** точная пропорция в u128, проверка нулевых assets и bounds, checked_sub вместо маскирующего underflow saturating_sub. Добавлены Rust unit/property-loop tests, в том числе отсутствие прибыли от deposit-withdraw и границы u64. **Локально не исполнены**; gate добавлен в CI. User minShares/deadline, модель дохода и историческая миграция LP требуют отдельной проверки.

### AOF-08 — Medium: energy regeneration переполнялся после 256 интервалов

Четыре инструкции сужали elapsed ticks до u8 до ограничения cap. После долгого отсутствия регенерация могла стать нулевой; дробное время терялось, а полная шкала могла сохранять старое время для повторного восстановления.

**Исправление:** общий `EnergyAccount::regenerate`, clamp до narrowing, сохранение остатка интервала, запрет накопления времени на cap и регрессии clock rollback/256 ticks. Layout account не меняется. Harvest Reaper теперь согласован по регистру. Rust execution остаётся обязательным CI gate.

### AOF-09 — Medium: неработающий и спонсируемый сервером prep-mint

Пользовательский Craft/Packs flow вызывал admin-only endpoint; кошелёк клиента не мог законно пройти его. Старый backend сам оплачивал mint/ATA и возвращал sig.

**Исправление:** proof для owner, user-funded rent/fees, частично подписанная mint keypair транзакция; main authority не оплачивает произвольные mint. Freeze authority у нового mint отсутствует. Guard допускает ровно этот шаблон. Это **перенос плательщика, не compression-экономия**. Подготовка пока отдельная транзакция: при неудаче craft пользователь несёт rent созданного mint.

### AOF-10 — High operational: ложный production deploy

Compose использовал PostgreSQL URL при committed SQLite provider/migrations, публиковал 5432 и имел default password. Worker commands требовали ts-node и services, отсутствовавших в runtime image. Docker build имел fallback, маскирующий ошибку.

**Исправление:** поддерживаемый single-host SQLite baseline вместо фиктивного PostgreSQL; без открытой БД/default password. Backend опубликован только на loopback за TLS proxy. Non-root, read-only rootfs, cap_drop, migrations, opt-in recovery worker. Workers компилируются отдельно, fallback build убран. **Контейнер не собран здесь: Docker отсутствует.** Это не решение масштабирования SQLite. PostgreSQL rollout должен быть отдельной полноценной data/schema migration.

### AOF-11 — Medium: секреты в логах и дорогая работа до rate limit

Pino HTTP мог сохранить Authorization/x-admin-token; sanitizer не защищал nested private keys и wallet proofs. Проверка подписи/БД выполнялась раньше general limiter.

**Исправление:** header redaction, recursive bounded redaction audit payload/query, URL без query в логах, rate limit до proof/DB, JSON body limit 32kb, x-powered-by выключен. Production требует admin token минимум 32 символа, отдельный proof domain и EXPECTED_GENESIS_HASH. Genesis проверяется до запуска API и перед поддерживаемыми signing flows. Длина token не доказывает случайность; оператор обязан создать его криптографически случайно.

### AOF-12 — Dependencies и frontend build

Удалён неиспользуемый `@solana/wallet-adapter-wallets` (оставлен Wallet Standard); обновлены Express и React Router в совместимых диапазонах. Исправлены отсутствующие `getToolNftCard/getToolName/getToolSubtitle` и несуществующее `meta.glow`: карточка использует существующий icon, без выдуманных image assets.

На момент проверки `npm audit --omit=dev`:

| Пакет | До | После |
|---|---:|---:|
| Frontend | 102: 1 critical, 15 high, 68 moderate, 18 low | 12: 0 critical, 0 high, 12 moderate |
| Backend | 15: 5 high, 10 moderate | 11: 3 high, 8 moderate |

Это число пакетов в advisory graph, **не число независимо эксплуатируемых дыр**; результат зависит от версии registry advisory database. На втором этапе обновлены qs/body-parser, Anchor parser явно закреплён override на `toml@4.2.0` (проверены parse Anchor.toml и prototype-pollution regression). SPL SDK удалён из browser runtime dependency graph: единственный production-вызов ATA derivation заменён компактной обёрткой над web3 PDA primitive, проверенной на 40 wallet/PDA векторах против SDK. Сам SDK оставлен **test-only**, поэтому dev advisories не исчезли.

Backend всё ещё использует SPL с high advisory bigint-buffer и имеет transitive web3 warnings; frontend имеет moderate advisories. `npm audit fix --force` предлагает несовместимые откаты Solana SDK — не применён. Не отключены audit/allowlist и не сделан вид, что отсутствие production high на frontend подтверждает весь supply chain. Нужен независимый reachability review оставшихся зависимостей.

### AOF-13 — High: marketplace transaction не связывала цену и выбранный лот

Добавлена отдельная инструкция **`marketplace_buy_bounded(max_price_lamports, expires_at)`**: positive max price, цена лота не выше max, срок строго в будущем и не дальше 300 секунд по chain clock; проверки до переводов. Старый `marketplace_buy` после upgrade возвращает FeatureDisabled.

**Почему новое имя/discriminator:** простой append аргументов к старой инструкции небезопасен при смешанном rollout — старый бинарник может проигнорировать trailing bytes. Новая инструкция не известна старому deployed binary и не должна молча стать неограниченной покупкой. Браузер отдельно запрещает legacy discriminator.

Frontend создаёт immutable intent из выбранного лота **до запроса API**: buyer, seller, treasury, mint, точная max price, срок +120 секунд. На границе подписи нужны ровно одна bounded-buy, 11 точных canonical accounts и 24 байта данных; один требуемый signer — текущий wallet. Допускаются только проверяемые compute budget инструкции и не более одной canonical idempotent ATA для buyer. Посторонние AOF-действия, подмена treasury, rent destination, цена/срок, trailing bytes/лишние accounts/signers, покупка без локального intent — отказ. Ответ API не является источником intent, а `sig` не заменяет wallet transaction при наличии intent.

Это не защита всех финансовых операций. Auction/rental/craft/LP требуют своих отдельных intent policies и on-chain bounds. Backend/frontend/program/IDL должны быть выпущены согласованно после runtime проверки.

### AOF-14 — Medium: неверная сериализация BN и округление денежных сумм

`query.ts` определял BN через несуществующий `_bn`: реальные Anchor BN превращались в объекты с words/negative вместо суммы. Используется `BN.isBN`, все BN/bigint отдаются десятичными строками; PublicKey — base58. Проверен u64::MAX. Listing creation разбирает SOL без float/round, buy подписывает исходную строку, отображение выбранной цены не округляет lamports. Остальные UI display/conversion paths ещё требуют отдельного обзора.

## Открытые production-блокеры

1. **Authority и supply.** Config.authority может mint resources/tools, выдавать payout, менять fees/economy/mints. Утечка hot key или admin token имеет большой blast radius. Нужны лимитированный operational authority, on-chain issuance caps (receipt для inbox уже добавлен, но не покрывает произвольный mint), отдельный governance/upgrade multisig, timelock/config bounds, runbook ротации. Просто вписать Squads PDA вместо Keypair сломает backend.
2. **Экономика не доказана.** Mining: 10 ресурсов/час Common и до 18 Legendary; repair burns возрастают с rarity (например Common 2 STONE + 3 WOOD за единицу, Legendary 45 + 70). Нельзя утверждать окупаемость без цен ресурсов и ограничений выпуска. Шесть villagers на кошелёк — не Sybil limit. Эмиссия/квоты должны жить on-chain, не только в rate limiter.
3. **Линейно растущий craft counter.** Цена растёт с общей minted_count, не с circulating supply. Burns не уменьшают counter: поздним игрокам дороже, рано или поздно checked arithmetic может остановить craft. Нужна утверждённая сезонная/предельная модель, а не произвольное изменение коэффициентов аудитором.
4. **Разрозненная типизация инструментов.** Packs исторически содержат `axe/pick/spear`, mining payout — `axe/pick/bow/reaper`, тесты используют также `pickaxe`. Нужен versioned enum + migration/compatibility; не угадывать ресурс для уже выпущенного spear. Существующий mint authority не отозван после mint1, canonical collection отсутствует; ownership PDA и реальный SPL balance должны проверяться для каждого пути/перевода.
5. **UI intent и slippage.** Marketplace buy покрыт AOF-13; для остальных операций нужны per-action max spend/min received/deadline, decimal-string/BN суммы без Number precision loss, защита изменения listing/auction quote и simulation deltas. Program allowlist — недостаточно.
6. **Отключённые механики.** Существующие fail-closed guards (sessions, hot market, collectors, rebirth, lottery, exploration, drum, random reroll и ряд off-chain features) не сняты. Backend mining запрещён в production, но это не on-chain global pause — прямые вызовы нужно учитывать отдельно. Нельзя рекламировать эти функции как live.
7. **DB/runtime.** Полный Prisma build/migrate/concurrency/restart/backup-restore test, PostgreSQL migration для multi-instance, distributed rate limits, proxy trust/Cloudflare configuration, queues/outbox, monitoring и incident response не подтверждены. SQLite baseline — только один хост с проверенными backup/recovery процедурами.
8. **Legacy surface.** `firebase.json` по-прежнему указывает на `functions/`; root CRA/netlify настройки не являются каноническим frontend release. Не деплоить legacy Firebase/Ronin функции. История Git проверена только по именам отдельных sensitive paths; нужен полноценный gitleaks history scan с redacted output и ротация потенциально ранее опубликованных ключей.
9. **Независимая проверка.** Нет свежих mainnet account/upgrade authority snapshots, verified builds, полного instruction fuzzing, chaos/load tests и независимого security sign-off. Все исправления Rust требуют сборки/тестирования перед каким-либо upgrade.

## Compression и снижение стоимости

Рекомендация: Bubblegum V2 pilot для **новых косметических/массовых активов**, позже отдельный ownership/custody adapter инструментов. Light/ZK — отдельная оценка compressed PDA/claim receipts и холодных token accounts. Подробности, первичные источники и обязательные proof/settlement tests: [docs/COMPRESSION_DESIGN.md](docs/COMPRESSION_DESIGN.md).

Добавлен offline cost model, а **не фиктивная интеграция**. Даже Bubblegum + обычный ToolData сохраняет значимый per-NFT rent. Учитывать protocol mint/transfer fees, реальную заполненность дерева, CU, DAS/prover и стоимость инфраструктуры. Никакие реальные NFT/деревья не создавались.
