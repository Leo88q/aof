# Что закрыто в игре и что нужно, чтобы включить (2026-09-30)

Задача владельца: «разблокируй везде все действия и включи, если не доделано то
доделай». Документ отвечает на три вопроса по каждому закрытому действию:
**что именно закрыто**, **почему** и **кто/что может это включить**.

Проверено по коду: `aof_backend/src/routes/*` (66 отказов 503 с кодом),
`aof-core/src/instructions/*`, `programs/*/src/lib.rs`, `frontend/src/**`.

> Кратко: **шесть переключателей (и три механики, которые включаются вместе с
> ними) работают сегодня вызовом админ-API** — ключ не нужен в коде, он у
> оператора; **Potato требует девнет-минта**, **сезонный пропуск — контракта V2
> (§3.6)**, **семь механик упираются в не задеплоенную механику в программе**
> (это не переключатель, а работа по контракту), **остальное — индексатор или
> гейты безопасности, которые нельзя открывать без риска для денег игрока.**
> Ниже — точный список и порядок.

---

## 1. Можно включить сегодня, без правок кода (оператор, админ-ключ)

Эти механики **уже реализованы** и в программе, и на бэкенде, и в клиенте.
Закрыты только значением конфигурации в сети. Включение — один вызов
админ-API на каждый пункт (все требуют заголовок админ-авторизации
`adminByMethod`; ключи в чат не попадают).

Добыча (пункты 1–6 таблицы) включается одной командой, которая сама проверяет
порядок и отказывается включать тумблер, пока выплат нет:

```
PREFLIGHT_OK=1 AOF_ENABLE_TARGET=devnet BASE_URL=<бэкенд> ADMIN_TOKEN=<токен> \
  scripts/enable-mining-devnet.sh          # сухой прогон, ничего не меняет
  # ...то же с --apply, чтобы реально включить
```

Скрипт читает `/admin/config/mining`, `/query/config`, `/query/material-mints`,
сверяет ровно те четыре адреса, что читает `aof_backend/src/lib/toolResourceMint.ts`
(`woodMint`, `stoneMint`, `meat`, `seeds`), и при любом пропуске/плейсхолдере
`1111…` выходит с кодом 3, не отправив ни одного POST. Поведение закреплено
девятью офлайн-тестами: `python3 scripts/test-enable-mining-devnet.py`.

| # | Механика | Что включить | Проверить после |
|---|---|---|---|
| 1 | **Добыча инструментов** (`start_mining`, `collect_mining`) | `POST /admin/config/mining {"enabled": true}` (тумблер `Config.mining_enabled`, [AUDIT F-27]) | `GET /admin/config/mining` → `miningEnabled: true`; клиент сам подхватит: `useMiningAvailability` опрашивает `/query/config` раз в 10 с |
| 2 | **Сбор добычи** | тот же тумблер + выплатные минты (пункты 3–5) | `POST /tools/collect-mining` перестаёт отдавать `MINING_NOT_CONFIGURED_ON_CHAIN` |
| 3 | **Адреса ресурсов в Config** | `POST /admin/set-resource-mints` (`foodMint, woodMint, stoneMint, seedsMint, waterMint, potatoMint`) | `GET /query/resource-mints` отдаёт все ключи, без `_UNAVAILABLE` |
| 4 | **MaterialMints (29 ресурсов)** | `POST /admin/init-material-mints` | `readMaterialMints` возвращает объект, а не ошибку |
| 5 | **Выплаты добычи по типам инструментов** | пункты 3–4: plasma → `Config.woodMint` (Circuit), silicon → `Config.stoneMint` (Silicon), data/quantum → `MaterialMints.meat` (Dataset), neural → `MaterialMints.seeds` (Neuron) | каждый из четырёх минтов существует, не `1111…`, с ожидаемым `mintAuthority` и 9 decimals |
| 6 | **Ремонт инструментов** (`repair`) | `Config.stoneMint`/`woodMint` = SILICON/CIRCUIT (тот же вызов, что п. 3) | `POST /tools/repair` перестаёт отдавать `REPAIR_RESOURCES_NOT_CONFIGURED`; кнопка сама включится — `RepairPage` читает `Config` |
| 7 | **Коллекционеры (Historian/Medallion)** | `POST /admin/config/collector-mint` на каждый разрешённый NFT-минт ([AUDIT F-16], allowlist) | `POST /collectors/stake` проходит; без записи в allowlist программа по-прежнему отвечает `CollectorMintNotAllowed` |
| 8 | **Потолки эмиссии** | `POST /admin/config/supply-cap` ([AUDIT F-03]) | `config/issuance-caps/init` → `set` |
| 9 | **Аварийный тормоз казны** | `POST /admin/config/vault-guard` ([AUDIT F-01]) | `capPerEpoch > 0` |
| 10 | **Платное событие «Potato»** (спины) | нужен **девнет-минт Potato** и казна: см. `docs/POTATO_DEVNET_SETUP.md`; адрес минта в репозиторий не коммитится | `npm --prefix aof_backend run inspect:potato-devnet` |

**Порядок для добычи:** 3 → 4 → 5 → 1 → 2. Если включить тумблер раньше
минтов, `start` пройдёт, а `collect` упрётся в `MINING_TOOL_REWARD_NOT_CONFIGURED`
— инструмент сгорит по прочности, выплаты не будет. Поэтому только в этом
порядке и только после `npm run preflight:mining-devnet` (читающая проверка
сети, ничего не подписывает).

## 2. Уже открыто, но выглядит закрытым

| Что | Как есть |
|---|---|
| Заявки на ресурсы **можно отменять** | `POST /orderbook/buy/cancel`, `/sell/cancel` живут и после паузы — эскроу возвращается |
| Возврат/раскрытие капсул, розыгрыш лотереи | статусы, `claim`/`refund` билетов работают; закрыта только **покупка** билета |
| Стейк/анстейк инструментов, сборка, packs | работают; добыча — только тумблер из §1 |
| Сезонный пропуск: чтение | владельцы уже купленных пропусков видят статус и VIP-оформление |
| Просмотр заявок, глубина рынка, цены | чтение ордербука работает |

## 3. Не переключатель: нужна работа по контракту (и деплой)

Здесь «включить» нельзя — можно только **дописать механику**, собрать и
задеплоить программу. Ниже — что именно не доделано и в чём риск, если открыть
как есть.

### 3.1 Ордербук ресурсов: цена в атомарных единицах (то, что на скриншоте)
`aof-core` принимает `price_lamports_per_unit` и умножает на `amount`, где
`amount` — атомы SPL (1 ресурс = 10^9 атомов). Значит, минимальная
выразимая цена — **1 lamport за атом = 1 SOL за целый ресурс**: рыночная
цена вида «0,001 SOL за ресурс» в этой шкале невыразима. Старая форма
подписывала «SOL за ресурс», то есть могла увести в эскроу в 10^9 раз больше
показанного. Что доделать: инструкции v2 с ценой **за целый ресурс** и
округлением вверх на эскроу, отдельный PDA (`resource_order_v2`), чтобы старые
эскроу-заявки остались отменяемыми, точная арифметика на BigInt (без
`parseFloat`), связанный с кошельком intent (`price`, `amount`, `total`) и
тесты квоты. После деплоя backend снимает `tradingPaused` с трёх маршрутов,
клиент получает форму покупки/продажи и кнопку сведения.

### 3.2 Лотерея: покупка без потолка цены
`buy_lottery_ticket` переводит **зашитую в код константу**; кошелёк не может
проверить цену, которую увидел игрок. Что доделать: параметр `max_price` в
инструкции + связанный intent. (Альтернатива без правки программы — префлайт-
симуляция транзакции и сверка списания; это дороже и слабее.)

### 3.3 Сессионные ключи
`session_create` отклоняется, пока резервирование не привязано к целевой
инструкции атомарно. Программа есть, «доделать» = изменить привязку в
`programs/aof-session-keys` и задеплоить.

### 3.4 Перерождение (rebirth)
`do_rebirth` берёт SOL и увеличивает счётчик, но **не сбрасывает сезонное
состояние и не сжигает активы**, обещанные правилами. Взять деньги за это —
необратимая экономическая ошибка, поэтому маршрут закрыт. Нужен полный сброс
одним действием + миграция уже существующих записей.

### 3.5 Событийный рынок инструментов (hot market)
`hot_market_buy/sell` в программе возвращают `TradingDisabled`: нет механики
передачи инструмента одним действием (покупатель и продавец не могут
обменяться без риска). Нужен обмен «инструмент ↔ SOL» и очередь продаж.

### 3.6 Сезонный пропуск, платный трек (V2)
Сегодня `claim_reward_handler` использует **одну** битовую карту на бесплатный
и платный трек и выдаёт одинаковую награду; XP начисляется вне сети. Нужен
`SeasonPass` V2 (раздельные треки, подписанные идемпотентные начисления,
потолки) — иначе продавать 0,15 SOL нельзя.

### 3.7 Внешний Potato (покупки, квесты, барабан)
Нет проверенного адреса минта, decimals и казны; старый барабан тратит
сырые атомы. Нужен минт, отдельный кас`PotatoBank` и V2-инструкции (см.
`docs/POTATO_DEVNET_SETUP.md`).

## 4. Не переключатель: нужен индексатор (чтение, не действия)

Эти маршруты отдают 503, потому что данных в сети нет, а подставлять ноль или
пустой список нельзя — игрок примет это за настоящее состояние. Лечится
индексатором/хранилищем, а не гейтом:
`quests` (прогресс, достижения), `portfolio` (оценка), `neighbors` (соседи и
лимиты), `trust` (профиль, лидерборд), `weather` (состояние и прогноз),
`privileges`, `vipStatus`/`season`, `energy` (баланс и трата), `farm` (состояние
участка), `daily`, `streaks`, `comeback`, `challenges`, `guild`, `npc`,
`traderRules`, `friend` (полив), `referralTiers` (привязка — есть канонический
`referralBind`), `query` (реестр ресурсов и балансы).

Правило проекта, которое здесь работает: «неизвестное показываем как
неизвестное», а не как ноль. Именно поэтому у каждого такого маршрута есть
человеческое объяснение в UI.

## 5. Закрыто ради безопасности денег — открывать нельзя

- **Цена ордербука** (§3.1) — расхождение в 10^9 раз.
- **Перерождение** (§3.4) — списание SOL без обязательств.
- **Покупка билета лотереи** (§3.2) — непроверяемая цена.
- **Платный сезон** (§3.6) — оплата за трек, которого нет.
- **Любая покупка Potato** (§3.7) — нет казны и decimals.
- **`/energy/spend`, `/sandbox/run-v3`, `/referral-tiers/bind`** — легаси-пути,
  заменённые каноническими инструкциями; открывать их = вернуть обход проверок.

## 6. Что сделано в этом заходе

- Инвентаризация всех 66 отказов 503 + программных гейтов + клиентских
  констант, с разбивкой «оператор / код / деплой / индексатор» (этот документ).
- `frontend/src/i18n/apiErrorCopy.ts`: добавлены человеческие объяснения для
  каждого технического кода, который бэкенд может показать игроку
  (`MINING_*`, `RESOURCE_*_UNAVAILABLE`, `SEASON_PASS_*`, `SESSION_KEYS_*`,
  `LOTTERY_*`, `ACTIVE_SEASON_UNAVAILABLE`, `ISSUANCE_CAP_EXCEEDED`,
  `REWARD_RECEIPT_CONFLICT`, `FRAUD_*`, `TRADER_RULES_*`) — на семи
  языках, чтобы после включения механик игрок не видел сырых кодов.
- Тест-страж: `tests/ui-regressions.test.ts` требует, чтобы у **каждого** кода
  из `aof_backend` было объяснение в `apiErrorCopy` — новый 503-код без
  перевода валит тест.
- `scripts/enable-mining-devnet.sh` — включение добычи (§1.1–1.5) одной
  командой, с жёстким порядком и предохранителями (только devnet, только
  после `preflight:mining-devnet`, только при живых выплатных минтах), сухой
  прогон по умолчанию, `--apply` для реального включения.
- `scripts/test-enable-mining-devnet.py` — девять офлайн-тестов на этот
  скрипт: включение происходит **только** после проверки выплат, при
  плейсхолдере/ненастроенном реестре/отсутствии ключа — ни одного POST.

## 7. Порядок включения (рекомендация)

1. §1.3–1.5 (минты ресурсов) → `preflight:mining-devnet` → §1.1–1.2 (добыча):
   всё это выполняет `scripts/enable-mining-devnet.sh --apply`, но только после
   того, как минты уже созданы (`aof_backend/scripts/initMintsV2.ts`).
2. §1.6 (ремонт) — тем же вызовом минтов.
3. §1.7 (коллекционеры) — allowlist на конкретные минты.
4. §3.1 (ордербук v2) — код + деплой + снятие паузы, затем §3.2 (лотерея).
5. §4 (индексатор) — отдельным проектом: без него половина витрин остаётся
   «неизвестно».
