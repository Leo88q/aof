# Devnet-first release gate: mining, Potato, season pass and VIP

**Status (2026-09-30): code prepared, NOT deployed or verified against devnet.** `watchtower/addresses.json` still labels the listed programs `reference-unverified`. No mainnet transaction is authorized by this plan. The owner confirms there are no historical `axe/pick/spear/bow/reaper` NFT ToolData accounts on the target network; resource-entry aliases are a different matter and remain intact.

## Delivered in this branch

- Retired the unrelated admin V3 simulator that still offered historical tool names and fabricated daily Potato issuance; `/sandbox/run-v3` now returns 503 instead of an obsolete forecast.
- Core accepts only `plasma_cutter`, `silicon_extractor`, `data_harvester`, `quantum_transmitter`, `neural_seeder`. Backend input validation, compendium/seasonal targets and player tool lookups match. Historical instruction/PDA/IDL names (for example `bowCommit`) are **ABI**, not a supported old NFT type; do not rename them without a versioned program migration.
- `/tools/collect-mining` now selects the exact resource mint checked by `collect_mining`: plasma → Circuit (`Config.woodMint`); silicon → Silicon (`Config.stoneMint`); data harvester and quantum transmitter → Dataset (`MaterialMints.meat`); neural seeder → Neuron (`MaterialMints.seeds`). Missing/invalid/zero reward mints fail closed; the backend matches the core's ASCII-case normalization. The mining flag read is single-flight, strict-boolean, error-closed and ignores stale responses after a local admin toggle; other backend instances rely on the short TTL and the on-chain guard; the admin API requires an explicit JSON boolean (`"false"` cannot accidentally enable mining). The on-chain instruction still checks payout mint, mint authority, completion, supply cap and `Config.mining_enabled`, then mints in the same transaction. Frontend reads `/query/config` on load and every 10 seconds and checks again before preparing a start/collect transaction; unknown/offline means disabled. On **new** core configs mining defaults to disabled; existing configs must be explicitly inspected and, if necessary, disabled by the operator.
- External Potato is NOT the in-game MIND. `Config.potatoMint` is an old ABI field for **MIND**; `QuestConfig.mascotMint` is a separate account field, not proof that an external Potato mint is configured. New drum commits, QuestConfig initialisation, new quest reward templates and season-pass purchases are closed at API level; the source program guards new drum commits and season purchases against direct RPC (only after a verified redeploy). Existing drum status/reveal/refund and historical quest claim paths remain; the UI labels historical event values as raw atomic units, not MIND or verified whole Potato. No Potato address, decimals or price has been invented.
- VIP API no longer advertises fee discounts, auto-trading or premium alerts that are not enforced. Existing season-pass ownership can still be read, but cannot be sold as a working bundle.

## 1. Full devnet mining runbook (operator-owned; do not paste keys into chat)

1. **Preflight and baseline.** Record git SHA and clean build artifact hashes. Install pinned Rust/Anchor/Solana toolchains in a secured CI/ops environment (`cargo`, `anchor`, `solana` are unavailable here); run `cargo test --locked --workspace --lib`, `anchor build`, repository readiness tests, frontend build/tests, backend Prisma generate/build. Compare IDL to source (`python3 scripts/check-idl-drift.py`, review its arguments), confirm deployed address declarations in `Anchor.toml`, source `declare_id!`, backend IDLs and `watchtower/addresses.json`. Inspect `scripts/verify-programs.sh` before running. Capture test logs and artifacts, not keypairs.
2. **Inspect network before sending any transaction.** From `aof_backend/`, run `npm run preflight:mining-devnet` (optionally point `DEVNET_RPC_URL` at a trusted devnet RPC and set `MINING_PREFLIGHT_REPORT` to a private path). This read-only probe checks the exact devnet genesis hash, IDL/source/registry IDs, executable upgradeable program owners and authorities, core Config/MaterialMints decoding, disabled mining flag, four distinct SPL reward mints, 9 decimals, mint authorities and finite supply caps. It exits nonzero if a check fails or registry entries remain `reference-unverified`; it does **not** update the registry or certify bytecode. A manual `Read-only mining devnet preflight (not a release)` Actions workflow can run the same unsigned probe and attach its public JSON report once that workflow is available on the repository's dispatchable branch; **it has not been triggered in this workspace**. Then run `solana config get`, `solana program show <core-id> --url devnet`, and, **after obtaining reproducible local `.so` artifacts**, `scripts/verify-programs.sh devnet <expected-upgrade-authority> target/deploy --require-bytecode`. This strict flag refuses missing `.so` files; a run without it is only an address/owner check, not release verification. Capture IDL/program hashes and account layout evidence for `mining_enabled`. Registry entries stay reference-only until the operator reviews this evidence. Never assume source changes are live on an existing deployment. Confirm player capacity, stake requirements and funding; the operator's devnet wallet may be funded from a faucet without sharing secrets.
3. **Fail-closed rollout.** If the existing on-chain flag is true, turn mining off using an authenticated admin action (`POST /admin/config/mining {"enabled":false}`) and verify the resulting signed transaction + Config PDA on devnet. If deploying a new program/config, it now boots false. Upgrade/deploy only with the authorized upgrade authority and a change ticket; verify deployed bytecode again. Exercise API and UI with flag false: both start and collect must refuse; test a directly assembled RPC transaction is also rejected. Before enabling, check `MaterialMints.meat/seeds` and `Config.woodMint/stoneMint` refer to the canonical mints (not default/zero) and are controlled by the expected mint authority; preserve snapshots of supply and balances.
4. **End-to-end pilot.** After validating disabled-path failures and the mint registry, explicitly enable mining *on devnet only* through the authenticated admin action, verify the on-chain flag and use five freshly issued canonical test NFTs owned by a consenting test wallet; test mint → stake → start (durability/capacity) → wait to completion → collect (ATA absent and present) → unstake, once per type. Verify exact recipient ATA mint and before/after balance against on-chain events, formula, elapsed hours, rarity and durability. Both dataset-producing types must pay the same Dataset mint. Reject old tool ids at mint/validation; confirm resource-input aliases still work where needed. Test wrong supplied payout mint, zero/unset mint, early collect, repeated collect, cap exceeded, user mismatch, insufficient durability and multiple overlapping sessions. Test toggling the flag off mid-session and back on; agree in advance how a blocked completed session will be safely settled. Test RPC/backend outage and UI fail-closed behaviour, not just happy paths.
5. **Soak and observability.** Monitor 24–72 hours on devnet with representative load and wallets; compare mint supply deltas to `MiningCollected` events and issued sessions, watch failed/signature-uncertain transactions, treasury/supply caps and RPC latency. Test abort/rollback: disable the flag on-chain, verify backend cache expiry (≤10 s nominal) and eventual UI refresh, stop new commits, settle existing sessions safely. Retain transaction signatures, hashes, logs, mint registry proof and an operator-signed checklist. **Only then** decide whether a separate mainnet launch is justified; repeat the preflight/approval process on mainnet rather than copying devnet IDs.

## 3. External Potato launch gate

**Owner decision (2026-09-30):** use the proposed whole-token 5 / 2–50 spin with 60/25/10/4/1% odds; VIP value is cosmetics and interface convenience, not gameplay yield or investment returns. The owner asked how to create the devnet mint; it does **not** exist in verified configuration yet. See [`POTATO_DEVNET_SETUP.md`](POTATO_DEVNET_SETUP.md) for secure devnet-only creation and the new unsigned `npm --prefix aof_backend run inspect:potato-devnet` check. Without a public mint address, compiled V2 contract and funded isolated PotatoBank vault, paid features stay closed; the raw-atom legacy drum is never a Potato checkout.

Obtain mint address from the owner via a secure ops configuration (never chat secrets); verify token-program owner, mint authority/freeze authority, decimals and metadata on the **target** cluster. Require `PotatoMint != Config.potatoMint` (MIND); validate the dedicated bank ATA belongs to Potato mint and the PotatoBank PDA. Keep the legacy quest treasury unchanged; V2 must use exact `u64` atoms (`whole_units × 10^decimals`, checked math), update events/API/UI to display decimal-formatted values only after verification. Preserve existing commitments on their original mint/version for refund/reveal; never reinterpret their raw units as new Potato. The old 5-atom spin/2–50-atom prizes do **not** imply 5 or 2–50 whole Potato.

For a proposed 5-unit spin with outcomes 2/5/10/20/50 at weights 60/25/10/4/1%, the expected payout is **4.75 Potato**, i.e. 95% of price before oracle, tx and treasury costs. This is a design example, not a live offer or a guaranteed margin. The legacy check for one `DRUM_MAX_PRIZE` is insufficient for multiple pending commitments. V2 now proposes a distinct paused PotatoBank PDA and isolated ATA with an on-chain reserved-liability ledger: 50 whole units **per open spin** reserved with payment/VRF in one transaction, released with settlement/refund. The V2 paid-commit remains unconditionally disabled until Rust compilation, generated IDL comparison, concurrent-spend/drained-bank/expiry/oracle-unavailability tests, immutable odds disclosures and signed devnet evidence. Commit route and sales must remain closed until deployed and verified. Existing commitments must remain claimable/refundable even when new sales are paused.

## 4. Remaining gated/unverified mechanics: release decisions

| Mechanic | Before offering it as live |
| --- | --- |
| Packs, forge, lottery, VRF/randomness | On-chain bytecode/IDL verified, deterministic quote, spend limit, clear public odds, robust reveal/refund after timeout, concurrent-liability funding; audited smoke tests and event-vs-balance reconciliation. No “guaranteed reward” copy from a UI-only flag. |
| Hot market, collectors, rentals/orderbook and auto trader | Enforce canonical ownership, trust/VIP and rate limits in program + API; deterministic settlement, fee split, escrow/cancellation and worker retry/idempotency. Leave controls disabled until worker actually executes. |
| Quest rewards, Potato, rebate/fee discounts | Verify external mint/treasury and units; reconcile claims and refund paths. Fee discount must be enforced in the same signed transaction (not a JSON `feeDiscountPct`). |
| Season/VIP, alerts, streak and energy | Version pass/rewards, cap verifiable XP, deliver paid cosmetics/alerts, disclose actual entitlements. No “8-minute energy” unless on-chain regen is updated and tested; otherwise show the real 20 cap/30-minute recovery. |
| Rebirth/session keys, guild/social and admin claims | Require verified deployed instructions, authorization and recovery/audit trail; otherwise keep descriptive screens explicitly marked unavailable. |
| Operations/legal/security | Maintain admin multisig/guardian pause, public incident/status process, reproducible deployment receipts and release decision. Technical build success does not supply missing legal/operator facts or network evidence. |

**Decision record required for mainnet:** verified devnet logs, risk owner sign-off, audited upgrade/program authority, economic caps and treasury, support/refund runbook, approved public terms/copy, smoke test signed by operator. Otherwise keep paid routes and unverified mechanisms closed.
