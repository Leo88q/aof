# Findings discovered during localization — deferred repairs

This is an **audit queue**, not a claim that these actions are currently safe or enabled on a deployed program. Per product priority, finish localization first; do not re-enable money-moving actions merely by changing UI copy. Reproduce against the current backend and deployed program before implementing repairs.

## Static metadata and install/share surfaces

- The initial `index.html` HTML metadata said *play-to-earn* and was English despite `lang="ru"`. The HTML fallback now uses a neutral Russian game description. Game/site/legal client routes refresh Open Graph and Twitter descriptions to match the selected locale, but social preview bots often do not execute JavaScript: every route still serves the same Russian fallback without server-side locale negotiation. Do not claim seven-language shared-link previews until a server/static-rendering solution is tested.
- `frontend/public/manifest.json` still has a single Russian description and a `finance` install category. `frontend/public/assets/brand/token-metadata.json` still labels NFORGE a `Utility Token` and includes DeFi and “trade the future” wording. Those public token/installation claims may be inaccurate or legally significant; check the actual issuance, entitlement and operator approval before modifying published token identity or marking its metadata translated. Neither resource is proof of a live earning feature.

## Verified visible locale miss corrected

- `FarmPlot` rendered the English `RARITY_META.label` on the selected structure in all seven languages, outside the Russian-literal inventory. It now indexes the existing seven-language rarity names by canonical rarity key, with a localized unknown fallback. Review other English-source metadata at runtime; do not treat **159/7** as a visible-coverage percentage. The same panel can still show `NaN/20` for a missing or malformed durability value; verify the balance/durability source and use an explicit unavailable state during the separate data-accuracy pass.

## Transactional market screens (high priority before release)

- **Shared transaction result gap:** `frontend/src/lib/txFlow.ts` falls through to `{ success: true }` for an object without `tx`, `sig`, `pending` or `error`. The handler has many farm, tool and market callers; a malformed/empty response can therefore appear successful even though nothing was signed or confirmed. The prior handler also rendered raw `pending` reasons, `response.error` and provider/RPC exception prose. These three display paths now show seven-language notices or known structured codes without changing the signing/confirmation decision; a signature is still retained for status checks. The **empty-envelope success remains unresolved**. Before release, make unrecognized responses fail closed, distinguish genuinely submitted signatures from malformed ones, and add direct transaction-response regression tests; static source checks are not proof of settlement.
- **Status display when signatures are absent:** offer and rental success notices append `${r.signature?.slice(...)}…`, which renders `undefined…` if `txFlow` returns success without a signature. Auction notices omit the fragment but still trust `success`, and the drum may announce a paid spin for an empty response. This is tied to the shared empty-envelope defect; verify actual submissions/confirmations and retain signatures before changing success copy or any money-moving logic.
- **Transient toast lifecycle:** `useFlash` now cancels an older timer when a new notice starts, discards a notice on language change and rejects late callbacks carrying an old language. `SeasonPassPage` now supplies the active locale to the hook. The shared farm `Toast` tags each message with the producing locale, hides it on a language switch and cancels an older dismissal timer before scheduling the new one. Static regression tests cover call-site tagging and the lifecycle wiring, but live browser switching, animation and timing still need verification; this does not prove payment or settlement.
- `frontend/src/pages/market/OfferPage.tsx`: creation converts user-entered SOL through `parseFloat` → `Math.round(… * 1e9)`; this is not an exact u64 amount. `handleTxResponse` receives no wallet-bound `TransactionIntent` for offer create/accept/cancel. It must verify the actual signed instruction, accounts, mint, amount and connected wallet. During the translation pass these calls were **not** changed.
- The same screen treats failed reads of wallet tools, listings and incoming offers as empty arrays; a network failure can therefore look like a confirmed empty inventory or empty market. Selection is not reset or revalidated on a wallet change, and the success refresh for an accepted offer calls `setSelOwn(m => m)`, which may not trigger a reload. The generic seven-language copy avoids promising that a zero count was verified, but the read-state model still needs repair.
- `frontend/src/pages/market/AuctionPage.tsx` and `RentalPage.tsx` also use `parseFloat`/`Math.round` for amounts or durations, `fmtSol` now accepts the active number locale, but still rounds to four decimal places, and failed reads can appear as empty results. The rental screen additionally clamps requested duration to the listing's range without telling the user, may send a zero hourly price if input is invalid, and renders some missing numeric fields as zero through `toNum`. Audit wallet ownership, exact quote binding, freshness, pending vs confirmed outcomes and authorized cancellation before treating transactional claims as verified facts. The rental translation changes copy/layout only, not these money-moving paths; no auction behavior was changed.
- `frontend/src/pages/market/AuctionPage.tsx`: a failed auction or wallet-tools read still looks like an empty list; a listing can show a zero or ended state for absent `endsAt`/bid fields (`toNum`). Bid/create use `parseFloat` and floating-point lamport rounding; the auction calls `handleTxResponse` without an instruction-bound intent, and that handler may return success for an otherwise empty API object. Closing the creation form on that result does not prove an on-chain auction. The translated success-path notice therefore only says a response was received and asks for an independent status check. The displayed amounts now use the active number locale, but still round to four decimal places in `fmtSol`. Investigate authorization of settlement and stale-wallet selections separately before enabling or endorsing these actions; only copy/layout changed in this pass.
- `frontend/src/lib/marketUtils.ts` now derives its Russian rarity/resource labels from the existing seven-language dictionaries; its unused legacy `timeLeftStr` now accepts a locale and defaults to Russian to preserve old calls; any future on-screen caller must supply the selected language. `fmtSol` and `fmtNum` accept a locale and the live market callers supply it. Check any future consumer of time labels without changing on-chain units.

Verify settlement and refund eligibility against the deployed program separately. The pre-signature transaction guard now localizes its rejection/warning strings and suppresses raw exception text, but the policy and hard stops are unchanged; provider/RPC errors and server-supplied pending reasons on paths *outside the shared transaction handler* may still leak in their original language; HTTP 2xx responses without JSON are now flagged as unconfirmed rather than displayed as raw English parse errors. Local wallet-adapter errors and local pending/error messages in `txFlow.ts` now follow the selected language. The shared handler additionally suppresses arbitrary provider/RPC prose, retains known guard/confirmation feedback and preserves an uncertain transaction signature. The diagnostic `NEED_WALLET` identifier is not translated.
- `frontend/src/site/content/mechanics.ts` formerly bundled obsolete Russian-only walkthroughs, some of which described paused mechanics as available. The three reachable site step lists now render their existing seven-language entries directly, and only stable related-guide routes remain. This is editorial retirement, **not** a contract fix.
